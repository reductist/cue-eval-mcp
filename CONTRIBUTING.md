# Contributing

We prefer changes to arrive through a short-lived topic branch and a pull
request:

1. Branch from `main`. Descriptive names such as `feature/...`, `fix/...`,
   or `docs/...` are encouraged but not required.
2. Keep the change focused and run the relevant tests or checks.
3. Open a pull request targeting `main`, explaining what changed and how it
   was checked.
4. Leave the pull request open for human review. Address any feedback, then let
   a maintainer merge it when it is ready.

Do not push changes directly to `main`. Treat that as project policy even
when the repository hosting plan cannot enforce it in settings.

GitHub does not let pull request authors approve their own work. This project
does not require an approval count: when a maintainer is also the author, they
should record the checks or review notes in the pull request and merge only
after completing that review.
